# 安全政策（摘要）

Vox Trust 目前处于 **1.0 之前**：规范版本 0.2（文件模式为候选发布版，音频内部分为实验性），软件为 v0.x。代码尚未经评审或审计。请不要依赖它来保护任何人。

- **受支持的版本：** 仅 `main` 上的最新发布版本。
- **披露目标：** 在收到有效报告后 7 天内确认收悉，并在 90 天内发布修复和安全公告（advisory）。这是一个志愿者项目，以上是目标而非保证。目前没有漏洞赏金，但所有报告都会被阅读，并可按你的意愿署名致谢。
- **范围：** 本仓库中的代码和规范，以及 vox-trust.github.io/demo/ 上的演示。不在范围内：需要受害者的密钥或设备才能实施的攻击（见威胁模型）。

## 如何报告漏洞

请通过 GitHub 的私密漏洞报告功能**私下**报告：

<https://github.com/vox-trust/vox-trust/security/advisories/new>

如果你无法访问该页面，请开一个最简的公开 issue，标题为 "security contact request"，**不要写任何细节**，维护者会安排私下沟通渠道。请勿为漏洞开公开 issue。请说明你发现了什么、如何复现，以及影响规范或代码的哪一部分。

## 漏洞还是设计反馈

- **漏洞（请私下报告）：** 能伪造出可通过验证的签章的方法；能通过策略检查的重放或拼接；参考代码中破坏已声明保证的缺陷。
- **设计反馈（请开公开 issue）：** 对威胁模型、规范草案或文档中某项主张的批评。欢迎对设计进行公开审视。

我们已知的攻击者和局限列在 [spec/THREAT-MODEL.md](../../spec/THREAT-MODEL.md) 中。
