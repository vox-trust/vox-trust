# How Vox Trust compares: notes and sources

The README's comparison table, cell by cell. "Measured" means we ran it on our own benchmark
([bench/results](../bench/results/)) with the same corpus, codecs and quality metrics as our
carriers. "Claimed" means the vendor's or a third party's published figure, which we have
not verified. Last checked 2026-10-02; corrections are welcome as issues.

## The difference in one line

Google SynthID, Meta AudioSeal, Resemble PerTh and Microsoft's Azure voice watermark mark
audio **their own AI produced**, so it can be recognised as synthetic. Deepfake detectors
**estimate** whether a voice is synthetic. Vox Trust lets a real speaker **seal their own
voice** with their own key, and anyone verifies the seal with ordinary cryptography.

## Vox Trust

- Proof bound to the speaker's key: HMAC-SHA-256 (circle mode) or Ed25519 with strict
  verification (public mode); [spec sections 5 and 6](../spec/SPEC.md).
- Altered seconds: file mode signs one SHA-256 digest per chunk and its position, so an edit
  or a swap is located to the chunk ([spec section 6](../spec/SPEC.md)).
- Offline verification: the Rust core runs as WebAssembly in the [browser demo](https://vox-trust.github.io/demo/), with no server.
- MP3, AAC, Opus: file mode survives only bit-exact copies. The experimental in-band carrier
  stdm-2 survived MP3, AAC and Opus 24/32 kbit/s in 100 % of windows
  ([results](../bench/results/2026-10-02-stdm-2/README.md)); it gives no verdict yet (copy
  attack, [threat model A11](../spec/THREAT-MODEL.md)).
- Phone calls: stdm-2 recovered 11 % of windows through AMR-WB 12.65 kbit/s.
- Cost: file mode seals or verifies 30 s of audio in under 1 ms (`cargo bench`); no model.

## Google SynthID (audio)

- Marks audio generated by Google's models; encoder and detector are not open source for
  audio; verification goes through Google's detector and partners
  ([Untrainable](https://untrainable.org/en/tools/synthid/), [Layer3 Labs, 2026](https://www.layer3labs.io/guides/synthid-explained)).
- Claimed 95.7 % detection after MP3 compression ([DataCamp](https://www.datacamp.com/tutorial/synthid)).
- Reported attack: MarkNull (USENIX Security 2026) is said to bring detection close to chance ([Layer3 Labs](https://www.layer3labs.io/guides/synthid-explained)).
- Not measured by us: no public detector.

## Meta AudioSeal

- Open source ([GitHub](https://github.com/facebookresearch/audioseal)); a generator and a
  detector that flags watermarked regions; 16-bit message.
- Measured ([results](../bench/results/2026-10-02-neural-baselines/README.md)): MP3, AAC,
  Opus down to 12 kbit/s, noise at 30 dB and echo 100 %; G.722 and AMR-WB 12.65 kbit/s 0 %;
  noise reduction 0 %; PESQ-WB 4.43.

## WavMark

- Open source academic watermark ([GitHub](https://github.com/wavmark/wavmark)), 16 bits per
  second. Not in the README table (a research model, not a product), but measured: noise
  reduction, echo and a 1 % tempo change 100 %, AMR-WB 12.65 kbit/s 31 %, PESQ-WB 4.12
  ([results](../bench/results/2026-10-02-neural-baselines/README.md)).

## Resemble AI PerTh

- Marks audio generated by Resemble; an open-source tool exists ([GitHub](https://github.com/resemble-ai/Perth)), and PerTh V2 is described on the vendor's site ([PerTh](https://www.resemble.ai/learn/models/perth), [announcement](https://www.resemble.ai/resources/the-watermark-cant-be-optional-anymore-so-we-made-it-the-default)).
- Claimed: near 100 % recovery after resampling or MP3. Not measured by us.

## Microsoft Azure AI Speech

- Watermarks speech made with Personal Voice and avatars; detection on request; claimed
  average detection above 99.7 % across editing scenarios ([transparency note](https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/speech-service/text-to-speech/transparency-note), [blog](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/create-personalized-voices-with-azure-ai-speech/4147073)).
  Not in the README table for space; same category as SynthID.

## Deepfake detectors (example: Pindrop Pulse)

- Estimates whether a caller's voice is synthetic, in real time in contact centres; claimed
  99 % on known engines and over 90 % on unseen ones with 2 s of speech, under 1 % false
  positives ([Pindrop](https://www.pindrop.com/article/pindrop-pulse-for-audio-deepfake-detection/)).
- Works on phone audio by design, but its answer is a probability, not proof of who spoke,
  and it can fall behind new generators.

## C2PA Content Credentials

- An open standard for signed provenance metadata on any media ([C2PA FAQ](https://c2pa.org/faqs/)).
  A signature can come from the capturing app or device, so it can vouch for a recording.
- Metadata travels in the file and can be removed by re-encoding or by platforms that strip
  it; C2PA uses watermarks as optional "soft bindings" to recover it. Vox Trust's file mode
  is close to C2PA in spirit and could be bridged to it ([roadmap](ROADMAP.md), phase 6).

## Research: MerkleSpeech

- Public-key speech provenance with per-chunk perceptual fingerprints committed in a signed
  Merkle tree, plus an in-band watermark to find the proofs ([arXiv 2602.10166](https://arxiv.org/abs/2602.10166)).
  The closest published idea to Vox Trust. Our own measurement of fingerprint binding
  ([study](../bench/results/2026-10-02-content-binding/README.md)) suggests that robust
  fingerprints can be forged by an adaptive attacker, which any such design has to answer.
